# MCP (agents)

## Abstract

The **PYNE MCP server** exposes the Pine toolchain to LLM hosts (Cursor, Claude, Inspector, Grok) over stdio by default, or over HTTP (`sse` / `streamable-http`) when `PYNE_MCP_TRANSPORT` is set. The same tools run from the shell with **`pyne mcp call`** and first-class **`pyne execute`** (no MCP SDK). Tools call library APIs in-process — they do not shell out. Serving needs `hoox-pyne[mcp]`; `call` / `execute` / `config` / `tools` do not. Tool names are prefixed `pyne_` so they never collide with AXIS `axis_*` / `app_*`. Compose publishes streamable-http on host `:5003`.

## Conceptual model

```mermaid
flowchart LR
  A[MCP host] -->|stdio or HTTP| S[pyne-mcp]
  CLI["pyne mcp call / pyne execute"] --> D[dispatch.call_tool]
  S --> O[pynescript.mcp.ops]
  D --> O
  O --> AST[parse / lint / convert]
  O --> RT[Runtime.run / compile]
  O --> LSP[hover / complete / builtins]
```

| Surface | Role |
| --- | --- |
| PYNE MCP | Language + runtime: parse, lint, convert, compile, execute, builtins |
| AXIS MCP | Chart PWA + Worker APIs (`POST /mcp`, optional tab bridge) |
| `pyne-lsp` | Editor language server (separate stdio process) |

Clients may enable PYNE MCP and AXIS MCP together.

## Interface surface

```bash
pip install "hoox-pyne[mcp]"
pyne mcp config          # print mcpServers JSON
pyne mcp tools           # catalog names
pyne mcp call lint script.pine
pyne mcp call execute script.pine --arg bars=50 --arg mode=interpret
pyne execute script.pine --mode interpret --bars 50
pyne mcp                 # stdio (blocks)
pyne-mcp                 # same as pyne mcp
python -m pynescript.mcp

# GHCR streamable-http image (compose also starts this as service mcp)
docker pull ghcr.io/hoox-sh/pyne/mcp:0.6.31
docker run --rm -p 5003:8080 ghcr.io/hoox-sh/pyne/mcp:0.6.31
```

```json
{
  "mcpServers": {
    "pyne": {
      "command": "pyne-mcp",
      "args": []
    }
  }
}
```

`pyne mcp config --module` uses `python -m pynescript.mcp` instead of the console script.

`pyne mcp call` and `pyne execute` / `symbols` / `parity` / `diagnostics` / `builtin` invoke the same ops in-process and print JSON (no stdio host, no `mcp` extra). TOOL may be `pyne_lint` or the short alias `lint`. Extra arguments: `--arg KEY=VALUE` (JSON-coerced) or `--json '{"bars":50}'`.

Every tool returns `{ "ok": true, ... }` or `{ "ok": false, "error", "kind", "line?", "column?" }`. Pine syntax errors are tool results, not protocol failures. Prefer `source=` (pasted script) over `path=`. Plot series are truncated (last N samples). Default data provider is `mock`. Runner tools use `PYNE_API_URL` / `ADMIN_TOKEN` and hit the network.

Catalog: [MCP tools](/pyne/docs/enduser/reference/mcp-tools).

## Code Mode (opt-in)

Set `PYNE_MCP_CODE_MODE=1` on the server process to add exactly two tools,
`search` and `execute`. With the flag unset the tool list is unchanged. Both
tools take one `code` string: a JavaScript async arrow function with no
parameters.

```text
search:  async () => catalog.filter((x) => x.group === "language" && x.short === "lint")
execute: async () => { const r = await pyne.language.lint({source}); return {ok: r.ok}; }
```

`search` receives a compact array of `{tool, short, group, risk, destructive,
summary, args, required}` and returns only the rows the code selects. `execute`
receives a `pyne` client:

| Binding | Meaning |
| --- | --- |
| `pyne.call(tool, args)` | call one catalog tool |
| `pyne.describe(tool)` | full signature for one tool |
| `pyne.<group>.<op>(args)` | namespaced call, e.g. `pyne.language.lint` |

Every call is re-resolved and re-dispatched through the same
`dispatch.call_tool` path as the direct tools. Destructive tools
(`risk=write`, the `pyne_runner_*` mutations) are refused in Code Mode unless
the operator also sets `PYNE_MCP_CODE_MODE_ALLOW_DESTRUCTIVE=1`.

### Sandbox

The code runs in a separate process, not in the Python server. The default
boundary is bubblewrap (`bwrap`): a new user/pid/net/ipc/uts/cgroup namespace,
a cleared environment, read-only binds of only the JavaScript runtime and its
shared libraries, a private tmpfs, and no host filesystem. The parent never
trusts the child; only JSON strings cross the bridge.

Code Mode needs a JavaScript runtime with `node:vm` (Node.js >= 18, or Bun) and
`bwrap`. If `bwrap` is absent the server fails closed with an explicit error.
Setting `PYNE_MCP_CODE_MODE_SANDBOX=subprocess` accepts a weaker, documented
mode: a plain child process with a cleared environment and a throwaway cwd, but
**host filesystem reads are still possible**. That opt-in is an operator
decision, not a security boundary. The streamable-http image ships `nodejs` and
`bubblewrap`; a container whose outer seccomp profile blocks user namespaces
still fails closed unless the operator chooses the weaker mode.

The sandbox never inherits the server environment, so `ADMIN_TOKEN` and API
keys stay in the parent. Reading `process.env`, `require`, or constructing a
function from a string fails inside the JavaScript context.

## Internals (repo paths)

- `src/pynescript/mcp/catalog.py` — canonical tool / resource / prompt names (docs + tests)
- `src/pynescript/mcp/server.py` — `MCPServer`, tool registration
- `src/pynescript/mcp/dispatch.py` — in-process `call_tool` (CLI `pyne mcp call`)
- `src/pynescript/mcp/cli.py` — Click `mcp` group + `execute` / `symbols` / `parity` / `diagnostics` / `builtin`
- `src/pynescript/mcp/ops/` — library-backed operations
- Extra: `[mcp]` in `pyproject.toml` (`mcp>=2.0,<3`, `lsprotocol`); surfaces `pyne-mcp` / `pyne mcp`
- Entry: `pyne-mcp = pynescript.mcp.__main__:main`
- Transport: `PYNE_MCP_TRANSPORT` (`stdio` default, `sse`, `streamable-http`) plus `PYNE_MCP_HOST` / `PYNE_MCP_PORT`

## Invariants & edge cases

- No disk writes (`format` / `convert` return source).
- `pyne_run` is the CLI compile + synthetic bars path. `pyne_execute` is `Runtime.run` (interpret / compile / auto, caller OHLCV, timeout).
- `pyne_download_builtins` **lists** pine-facade templates; it does not write files.
- Hover / complete / signature reuse LSP handlers; they need `lsprotocol` (pulled in by `[mcp]`).

## Worked examples

```text
User: lint this script and run 50 bars
Agent: pyne_lint({source}) → pyne_run({source, bars: 50})
```

```text
User: what does ta.sma take?
Agent: pyne_builtin({name: "ta.sma"})
```

## Failure modes

| Symptom | Cause |
| --- | --- |
| `MCP extra missing` | `pip install "hoox-pyne[mcp]"` for stdio. `pyne execute` / `mcp call` run without the extra |
| `ok: false`, `kind: parse` | Syntax error; `line` / `column` set when known |
| `kind: network` | Runner / non-mock `pyne_data` / facade list |
| Large plot dumps | Raise `sample` only as needed (max 64) |
