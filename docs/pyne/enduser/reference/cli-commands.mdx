# CLI Commands Reference

## Abstract

Machine-oriented reference for every command on the preferred **`pyne`** Click group
(alias **`pynescript`**; `src/pynescript/__main__.py`). Install via **[`hoox-pyne`](https://pypi.org/project/hoox-pyne/)**
(`pip install hoox-pyne`). For workflows see the [CLI guide](/pyne/docs/enduser/guides/cli).
The language server is a **separate** console script (`pyne-lsp`; alias `pynescript-lsp`).

**Version option:** `pyne --version` / `-V` reports `pynescript.__about__.__version__`
(e.g. `0.7.0`). Global `--no-color` honors `NO_COLOR`.

## Command index

| Command             | Aliases       | Purpose                                                    |
| ------------------- | ------------- | ---------------------------------------------------------- |
| `check`             |               | Parse-only validation (CI-friendly exit codes)             |
| `format`            | `fmt`         | Parse → unparse (structural format)                        |
| `convert`           |               | Rewrite older Pine toward v5 or v6                         |
| `parse-and-dump`    | `dump`, `ast` | AST dump                                                   |
| `parse-and-unparse` | `unparse`     | Round-trip source                                          |
| `lint`              |               | Static diagnostics (JSON / fail-on)                        |
| `compile`           |               | Transpile or compile-check (Numba path)                    |
| `prewarm`           |               | Warm Numba builtins / script IR caches (H2)                |
| `run`               |               | Compile + execute on synthetic OHLCV                       |
| `execute`           |               | `Runtime.run` JSON (MCP `pyne_execute`)                    |
| `symbols`           |               | Outline functions / inputs / plots                         |
| `parity`            |               | Interpret vs compile last plot values                      |
| `diagnostics`       |               | Parse errors + lint in one JSON list                       |
| `builtin`           |               | Look up one Pine builtin (`ta.sma`)                        |
| `optimize`          |               | Search `input.*` values over N interpret Runtime runs      |
| `data`              |               | Fetch market bars                                          |
| `runner`            |               | Hosted scripts on the Pro API (`deploy` / `tick` / `list`) |
| `key`               |               | Mint Pro API keys against the configured store             |
| `serve`             |               | Start the Pro API (`backend.app:main`)                    |
| `datafeed`          |               | CCXT datafeed gateway (`datafeed serve`)                  |
| `info`              | `ls`          | Version + optional extras                                  |
| `mcp`               |               | Stdio server, `config`, `tools`, in-process `call`         |

```bash
pyne --help
pyne --version
pyne <command> -h
# alias: pynescript …
```

### `pyne check`

Validate that path(s) parse as Pine Script.

| Kind     | Name          | Default    | Description                                   |
| -------- | ------------- | ---------- | --------------------------------------------- |
| argument | `PATHS…`      | (optional) | Files and/or directories; omit or `-` → stdin |
| option   | `--encoding`  | `utf-8`    | Text encoding                                 |
| option   | `-q, --quiet` | off        | Exit code only                                |
| option   | `--ext`       | `.pine`    | When PATH is a directory, only this suffix    |

```bash
pyne check script.pine
pyne check scripts/ --ext .pyne
pyne check -q strategy.pine   # exit 0/1 only
cat x.pine | pyne check -
```

**Exit:** `0` all ok; `1` any parse failure.

### `pyne format` (`fmt`)

Canonicalize Pine by parse → unparse (structural, not a full style formatter).

| Kind     | Name                | Default  | Description                                |
| -------- | ------------------- | -------- | ------------------------------------------ |
| argument | `PATH`              | required | File or `-` (stdin)                        |
| option   | `--encoding`        | `utf-8`  |                                            |
| option   | `-w, --write`       | off      | Write back to PATH (not for stdin)         |
| option   | `--check`           | off      | Exit `1` if format would change (no write) |
| option   | `-o, --output-file` | `-`      | Output when not using `--write`            |

```bash
pyne format script.pine            # stdout
pyne fmt script.pine -w
pyne format script.pine --check    # CI drift gate
```

### `pyne convert`

Rewrite older Pine toward v5 or v6. `--to 6` converts **any** older version
(missing `//@version` counts as v1): color / `n` / timeframe idents, `ta.*` /
`math.*` / `request.*` namespaces, `study(` → `indicator(`, typed `input.*()`,
`iff` / `offset`. Not a semantic v6 migrator (bool-as-int, `na`).

| Kind     | Name                | Default  | Description                        |
| -------- | ------------------- | -------- | ---------------------------------- |
| argument | `PATH`              | required | File or `-` (stdin)                |
| option   | `--to`              | required | `5` / `6` / `v5` / `v6`            |
| option   | `--encoding`        | `utf-8`  |                                    |
| option   | `-w, --write`       | off      | Write back to PATH (not for stdin) |
| option   | `-o, --output-file` | `-`      | Output when not using `--write`    |

```bash
pyne convert old.pine --to 6
pyne convert strategy.pine --to 6 -w
```

### `pyne run`

Compile and execute on deterministic synthetic OHLCV (same compile pipeline as
Pro API `mode=compile`). **No `--mode`.** Does **not** call `Runtime.run`. Prefer
package `pynescript.runtime.Runtime` / Pro API for real bars, `libraries=`, and
`timeout_seconds`.

| Kind     | Name          | Default  | Description                 |
| -------- | ------------- | -------- | --------------------------- |
| argument | `PATH`        | required | Pine file                   |
| option   | `--encoding`  | `utf-8`  |                             |
| option   | `--bars`      | `50`     | Synthetic bar count         |
| option   | `--json`      | off      | Plot series summary as JSON |
| option   | `-q, --quiet` | off      | Errors / exit only          |

```bash
pyne run strategy.pine --bars 100
pyne run strategy.pine --json
```

### `pyne optimize`

Search `input.*` values for a **`strategy()`** script. Loops interpret `Runtime` (not `/backtest/quick`). Requires `--space` JSON.

| Kind     | Name             | Default     | Description                                             |
| -------- | ---------------- | ----------- | ------------------------------------------------------- |
| argument | `PATH`           | required    | Pine file (`-` = stdin)                                 |
| option   | `--encoding`     | `utf-8`     |                                                         |
| option   | `--bars`         | `120`       | Synthetic bar count (min 8)                             |
| option   | `--trials`       | `20`        | Trial budget (max 200)                                  |
| option   | `--space`        | required    | JSON `{"params":[{"name","kind","min","max"}]}`         |
| option   | `--sampler`      | `auto`      | `auto` \| `random` \| `tpe` \| `grid`                   |
| option   | `--objective`    | `composite` | `composite` \| `net_pnl` \| `profit_factor` \| `calmar` |
| option   | `--validation`   | `holdout`   | `holdout` \| `walk-forward` \| `in-sample`              |
| option   | `--train-bars`   | derive      | Walk-forward train window                               |
| option   | `--test-bars`    | derive      | Walk-forward test window                                |
| option   | `--step-bars`    | derive      | Walk-forward step (default: the test window)            |
| option   | `--holdout-frac` | `0.3`       | Holdout test fraction                                   |
| option   | `--seed`         | unset       | RNG seed                                                |
| option   | `--json`         | off         | Full study JSON                                         |

`--validation walk-forward` derives windows from `--bars` when the bar flags are omitted: `train=max(8, bars*2//3)`, `test=max(4, bars//6)`, `step=max(1, test)` (so default `--bars 120` → 80/20/20). Explicit `--train-bars` / `--test-bars` / `--step-bars` override that. The CLI refuses walk-forward when `--bars < train+test`. All-errored studies exit 1 even if the study status is `success`.

```bash
pyne optimize strat.pine --trials 20 --sampler tpe \
  --space '{"params":[{"name":"Fast","kind":"int","min":3,"max":12}]}'
pyne optimize strat.pine --validation walk-forward --bars 120 --trials 20 \
  --space '{"params":[{"name":"Fast","kind":"int","min":3,"max":12}]}'
pyne optimize strat.pine --validation walk-forward --train-bars 80 --test-bars 20 \
  --space '{"params":[{"name":"Fast","kind":"int","min":3,"max":12}]}'
```

Library: `pynescript.optimize.run_study`. HTTP: [POST /optimize](/pyne/docs/api/endpoints/optimize).

### `pyne corpus`

Rich front-end over the open-source Pine corpus (`tests/data/set0N`). Runs scripts through `Runtime` (or parse-only) and writes CSV + summary under `.cache/`.

| Subcommand | Role                                                                    |
| ---------- | ----------------------------------------------------------------------- |
| `list`     | Show available sets and `.pine` counts (`--json`, `--data`)             |
| `run`      | Execute sets (`--sets`, positional set names, `--mode`, `--workers`, …) |

| Kind     | Name                       | Default                            | Description                                            |
| -------- | -------------------------- | ---------------------------------- | ------------------------------------------------------ |
| option   | `--sets`                   | `set01,set02,set03`                | Comma-separated corpus sets                            |
| argument | `SETS_ARGS`                | optional                           | Extra set names (`pyne corpus run set01 set02`)        |
| option   | `--mode`                   | `compile`                          | `interpret` \| `compile` \| `auto` \| `run` \| `parse` |
| option   | `--timeout`                | `20`                               | Per-script seconds                                     |
| option   | `--bars`                   | `50`                               | Synthetic OHLCV length                                 |
| option   | `--workers`                | `6`                                | Process pool size                                      |
| option   | `--out`                    | `.cache/runtime_corpus_…csv`       | Results CSV                                            |
| option   | `--resume`                 | off                                | Skip files already in `--out`                          |
| option   | `--data`                   | `tests/data` / `$PYNE_CORPUS_DATA` | Corpus root                                            |
| option   | `--plain` / `--rich`       | auto                               | Disable or force Rich                                  |
| option   | `--strict` / `--no-strict` | strict                             | Exit 1 on residual failures                            |

```bash
pyne corpus list
pyne corpus run --sets set01,set02 --mode compile
pyne corpus run set01 --mode parse --workers 4 --plain
```

Engine module: `pynescript.util.corpus_runtime` (also used by `scripts/corpus_run_runtime.py`).

### `pyne runner`

HTTP client for the optional Flask hosted runner (`PYNE_RUNNER=1`). Group options apply to every subcommand.

| Kind   | Name      | Default                 | Description                     |
| ------ | --------- | ----------------------- | ------------------------------- |
| option | `--url`   | `http://127.0.0.1:5002` | Pro API origin (`PYNE_API_URL`) |
| option | `--token` | empty                   | `X-Admin-Token` (`ADMIN_TOKEN`) |

| Subcommand                 | Role                                              |
| -------------------------- | ------------------------------------------------- |
| `deploy PATH`              | Read a `.pine` / `.pyne` file and `POST /scripts` |

```bash

pyne runner tick --id demo --force
pyne runner list
pyne runner history --id demo --limit 10
pyne runner --url http://127.0.0.1:5002 jobs
```

Full HTTP contract: [hosted runner](/pyne/docs/api/endpoints/runner).

### `pyne key`

Mint Pro API keys against the same store the HTTP API uses. The command calls
`APIKeyStore.create_key` in `backend/middleware/auth.py` — the same path as
[`POST /auth/create_key`](/pyne/docs/api/auth-and-keys) — so key format, hashing,
and tier limits have one implementation.

| Kind       | Name     | Default | Description                                         |
| ---------- | -------- | ------- | --------------------------------------------------- |
| subcommand | `create` |         | Mint one key and print the raw secret once          |
| option     | `--tier` | `hobby` | `free` \| `hobby` \| `pro` \| `team` \| `enterprise` |
| option     | `--json` | off     | Machine-readable `{status, api_key, key_id, tier}`  |

`STORE_BACKEND` selects where the key is written:

| Value            | Persistence                                          |
| ---------------- | ---------------------------------------------------- |
| `json` (default) | JSON file at `API_KEY_STORE`                         |
| `sqlite`         | SQLite file at `API_KEY_STORE_SQLITE` (multi-worker) |
| `redis`          | Redis at `REDIS_URL` (multi-replica)                 |

**`ADMIN_TOKEN` is required.** The command refuses to mint when the variable is
unset or blank, and it has no bypass flag. This mirrors the HTTP route: an unset
`ADMIN_TOKEN` means "admin minting disabled", not "open minting". The CLI shares
the process with the store, so there is no token to compare — the check is a
presence gate that keeps both entry points equally hard to open.

```bash
export ADMIN_TOKEN=...
pyne key create                     # hobby tier
pyne key create --tier pro
pyne key create --tier hobby --json
```

`--json` prints the same envelope the HTTP route returns:

```json
{
  "status": "success",
  "api_key": "pyn_…",
  "key_id": "a1b2c3d4e5f6",
  "tier": "hobby"
}
```

**The raw key is shown once.** The store keeps only a hash — a PBKDF2
(`v2:`-prefixed) digest on `sqlite` and `redis` — so the secret cannot be
recovered later. Copy it when it is printed.

Minting needs the Pro API backend (`backend/`), which ships with the source
checkout rather than the wheel. Install its dependencies with
`pip install "hoox-pyne[pro]"` and run the command from the checkout.

### `pyne execute`

`Runtime.run` on PATH (MCP `pyne_execute`). Prints the JSON envelope. Unlike `pyne run`, this is interpret/compile/auto with optional caller OHLCV rows.

| Kind     | Name                       | Default       | Description                                                        |
| -------- | -------------------------- | ------------- | ------------------------------------------------------------------ |
| argument | PATH                       |               | File or `-` (stdin)                                                |
| option   | `--mode`                   | `auto`        | `interpret` / `compile` / `auto`                                   |
| option   | `--bars`                   | `50`          | Synthetic bars when `--ohlcv` is omitted                           |
| option   | `--ohlcv`                  |               | JSON array of `{time,open,high,low,close,volume?}` rows, or a file |
| option   | `--inputs`                 |               | JSON object of `input.*` overrides, or a file                      |
| option   | `--timeout`                | 30s (cap 120) | Seconds                                                            |
| option   | `--sample`                 | `8`           | Trailing plot samples (max 64)                                     |
| option   | `--trades`                 |               | Include strategy trade extras                                      |
| option   | `--ticker` / `--timeframe` | `MCP` / `1m`  | Runtime identity                                                   |

```bash
pyne execute script.pine --mode interpret --bars 50
pyne execute script.pine --ohlcv bars.json --inputs '{"len": 14}'
```

Exit 1 when `ok` is false.

### `pyne mcp`

Stdio Model Context Protocol server, plus in-process tool execution. Serving stdio requires `pip install "hoox-pyne[mcp]"`. `config`, `tools`, and `call` do not.

| Kind       | Name               | Description                                         |
| ---------- | ------------------ | --------------------------------------------------- |
| (no args)  |                    | Serve MCP on stdio (`pyne-mcp`)                     |
| subcommand | `config`           | Print `mcpServers.pyne` JSON                        |
| subcommand | `tools`            | List catalog tool names (`--json` array)            |
| subcommand | `call TOOL [PATH]` | Run a tool in-process and print JSON                |
| option     | `--module`         | `config` only: `python -m pynescript.mcp`           |
| option     | `--source` / `-s`  | `call`: inline Pine (overrides PATH)                |
| option     | `--arg` / `-a`     | `call`: `KEY=VALUE` (JSON-coerced; repeatable)      |
| option     | `--json`           | `call`: extra arguments object (inline or file)     |
| option     | `--name`           | `call`: shortcut for `--arg name=` (`pyne_builtin`) |

```bash
pip install "hoox-pyne[mcp]"
pyne mcp config
pyne mcp tools
pyne mcp call lint script.pine
pyne mcp call execute script.pine --arg bars=24 --arg mode=interpret
pyne mcp
pyne-mcp
python -m pynescript.mcp
```

Tools, resources, prompts: [MCP tools](/pyne/docs/enduser/reference/mcp-tools). Guide: [MCP (agents)](/pyne/docs/enduser/guides/mcp).

### `pyne serve`

Start the existing Pro API. The command calls `backend.app.main` — the same
entry as `python -m backend.app` and `make run`. It does not build a second
server. Production gunicorn still loads `backend.app:app`.

| Kind   | Name       | Default | Description                                      |
| ------ | ---------- | ------- | ------------------------------------------------ |
| option | `--dry-run` | off     | Print `backend.app:main` and do not listen       |

`HOST` (default `127.0.0.1`) and `PORT` (default `5002`) are read by that entry.

```bash
pyne serve
pyne serve --dry-run
```

If the `backend` package or the `[pro]` extra is missing, the command exits
non-zero and prints:

```bash
pip install 'hoox-pyne[pro]'
```

---

### `pyne datafeed serve`

Start the existing CCXT datafeed gateway. The command calls
`backend.datafeed_app.main` — the same entry as `python -m backend.datafeed_app`.
Production gunicorn loads `backend.datafeed_app:app` (`GUNICORN_APP`).

| Kind       | Name        | Default | Description                                           |
| ---------- | ----------- | ------- | ----------------------------------------------------- |
| subcommand | `serve`     |         | Start `backend.datafeed_app:main`                     |
| option     | `--dry-run` | off     | Print `backend.datafeed_app:main` and do not listen   |

`HOST` (default all interfaces, same as `python -m backend.datafeed_app`) and
`PORT` (default `8080`) are read by that entry. `pyne datafeed` with no
subcommand prints this group's help.

```bash
pyne datafeed serve
pyne datafeed serve --dry-run
```

If the `backend` package or the `[datafeed]` extra is missing, the command
exits non-zero and prints:

```bash
pip install 'hoox-pyne[datafeed]'
```

## Invariants

- Aliases: `dump`/`ast` → `parse-and-dump`; `unparse` → `parse-and-unparse`; `fmt` → `format`; `ls` → `info`.
- Prefix match works when unique (`pynescript ch` → `check`).
- `check` walks directories; dump/format take a single file.
- **Docker:** `pynescript-cli` image `ENTRYPOINT` is `pynescript` (non-root).
- **Standalone binaries:** GitHub Release `pynescript-cli-*` (Nuitka).

## Failure modes

| Situation                         | Result                                   |
| --------------------------------- | ---------------------------------------- |
| Parse failure (`check` / dump)    | Non-zero exit                            |
| Format `--check` drift            | Exit `1`                                 |
| Lint threshold                    | Non-zero per `--fail-on`                 |
| Compile without numba (full path) | Clear error; `--emit` still works        |
| Provider failure                  | Click error with message                 |
| Missing `ccxt` for data           | Import/provider error → install `[data]` |
| `pyne key` without `ADMIN_TOKEN`  | Click error; nothing is minted           |
| `pyne key` without Pro backend    | Clear error → run from a checkout        |
| `pyne serve` without backend or `[pro]` | Non-zero; prints `pip install 'hoox-pyne[pro]'` |
| `pyne datafeed serve` without backend or `[datafeed]` | Non-zero; prints `pip install 'hoox-pyne[datafeed]'` |
