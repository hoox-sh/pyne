# Inlay Hints

## Abstract

Inlay hints surface two things: **inferred types** next to simple `name = expr` assignments when no explicit type annotation is present, and **parameter names** before positional arguments of builtin and user function/method calls (`ta.sma(close, 14)` → `source:` / `length:`). Inference uses the scope-aware symbol index first (annotated declarations, UDT fields/methods, user return types, builtin metadata) and falls back to the shallow constant/`input.*`/`ta.*` rules. Ambiguous operators are skipped rather than guessed wrong. Hints are filtered to the client's requested range. `inlayHint/resolve` fills `textEdits` that insert the type annotation; parameter-name hints do not insert text.

## Conceptual model

```mermaid
flowchart TD
  PARSE[parse source] --> WALK[walk Assign and Call]
  WALK --> ASG{simple Name target, no type, has value?}
  ASG -->|yes| INF[_infer_type RHS]
  INF -->|const / series / input / → type| THINT[": type_label" at end of name]
  INF -->|None| SKIP[skip]
  ASG -->|no| SKIP
  WALK --> CALL{dotted builtin Call?}
  CALL -->|yes| NAMES[_param_names_from_info]
  NAMES --> PHINT["name:  at start of positional arg"]
  CALL -->|no| SKIP
  THINT --> RES[inlayHint/resolve textEdits]
  PHINT --> NOOP[resolve no-op]
```

Example mental model (from module docstring):

```text
length = 14                 →  length: const int
rsi = ta.rsi(close, 14)     →  rsi: series float   (from metadata detail)
n = input.int(5, "n")       →  n: input int
ta.sma(close, 14)           →  ta.sma(source: close, length: 14)
```

## Interface surface

| Method | Capability |
| --- | --- |
| `textDocument/inlayHint` | `InlayHintOptions(resolve_provider=True)` |
| `inlayHint/resolve` | fills `textEdits` on type hints |

Handlers: `features/inlay_hints.py` → `handle_inlay_hints` (receives version-matched `tree=doc.valid_ast`) and `handle_inlay_hint_resolve`.

### Assignment type hints

| Field | Value |
| --- | --- |
| `position` | End of target identifier (`lineno-1`, `col_offset + len(id)`) |
| `label` | `": {type_label}"` |
| `kind` | `InlayHintKind.Type` |
| `tooltip` | `Inferred type: {type_label}` |
| `data` | same insert text, so resolve does not re-parse |

### Parameter-name hints

Emitted for positional args of `module.attr(...)` when `get_builtin("module.attr")` hits. Real snippet placeholder names win; generic `paramN` snippets fall through to the longest of the `detail` signature, documentation, and a well-known Pine v6 map (`ta.sma`/`ema`/`rsi` → `source`/`length`, `ta.atr` → `length`, `ta.correlation` → `source1`/`source2`/`length`, `strategy.entry` → `id`/`direction`/`qty`, `input.int` → `defval`/`title`, plus `ta.cci`/`roc`/`mom`/`linreg`/`adx`/`mfi`/`bbw`/`dpo`/`crossover`/`crossunder`).

| Field | Value |
| --- | --- |
| `position` | Start of the positional argument |
| `label` | `"{name}: "` |
| `kind` | `InlayHintKind.Parameter` |
| `data` | omitted |

Named kwargs (`length=14`) skip the matching slot. Parameter hints have no insertable type annotation.

`handle_inlay_hints` returns `[]` for empty source, `None` if parse fails (client typically treats as no hints).

### Resolve

`inlayHint/resolve` inserts the type annotation at the hint position:

1. Already-resolved hints (existing `textEdits`) are returned unchanged.
2. `InlayHintKind.Parameter` is a no-op — must not splice names into the call.
3. Insert text comes from `hint.data` (preferred) or the label string / label parts.
4. Only strings that start with `": "` are treated as type annotations.
5. One `TextEdit` with a zero-width range at `hint.position`.

## Internals

### Constant mapping

| Python value | Label |
| --- | --- |
| `bool` | `const bool` |
| `int` | `const int` |
| `float` | `const float` |
| `str` | `const string` |

### Builtin bare names

`open`, `high`, `low`, `close`, `volume`, `hl2`, `hlc3`, `ohlc4` → `series float`; time / bar index vars → `series int`; `na` → `na`.

### Calls

- `input.{int,float,bool,string,color,symbol,session,source,time,timeframe,price}` → `input {attr}`
- `ta|math|str|color.{attr}` → parse `detail` after `→`, else fallback `"series"`

### Walk

Recursive over `_fields` (same pattern as workspace symbol collection) — not limited to script top-level; nested function assigns and nested calls can receive hints.

| Path | Role |
| --- | --- |
| `features/inlay_hints.py` | Collection + inference + resolve |
| `providers/builtin_metadata.py` | Return-type detail and parameter names |

## Invariants and edge cases

1. **Explicit `name: type = …` suppresses type hints** (`node.type is not None`).
2. **Tuple / attribute targets** are ignored for type hints.
3. **BinOp / Compare / Conditional** return `None` — no speculative arithmetic types.
4. **Metadata quality bounds accuracy** — missing `→` in detail yields coarse `series`; missing param names yields no parameter hints.
5. **Resolve inserts types only** — parameter labels (`source: `) are display-only.
6. **Malformed / empty resolve input does not throw** — the hint is returned as-is.

## Worked example

```pinescript
//@version=6
indicator("hints")
length = 14
src = close
avg = ta.sma(src, length)
period = input.int(20, "Period")
```

Expected hints (when parse + metadata succeed):

- `length` → `: const int` (type; resolve inserts `: const int` at the end of `length`)
- `src` → `: series float`
- `avg` → type from `ta.sma` detail (typically series float) or `series`
- `period` → `: input int`
- `ta.sma(src, length)` → `source:` before `src`, `length:` before `length`

`avg` will not get a hint derived from `length`’s type through the call graph — only the call’s known return shape. Resolve on a parameter hint leaves the call text unchanged.

## Failure modes

| Symptom | Cause |
| --- | --- |
| No hints on file | Parse error → `None` |
| `ta.*` always `: series` | Metadata detail lacks `→` segment |
| No `source:` / `length:` on a builtin call | Not a dotted builtin, named kwargs, or metadata/snippet names missing |
| Apply-type-inlay does nothing on a param hint | Expected: resolve skips `InlayHintKind.Parameter` |
| Hints mid-identifier | Incorrect `col_offset` on AST node — builder issue |
