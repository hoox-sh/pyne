# Code lens

## Abstract

`textDocument/codeLens` places one lens row above each top-level `indicator(...)` / `strategy(...)` / `library(...)` call. Lenses are client commands, not server executions: clients that do not register the commands can ignore them.

## Interface surface

- Method: `textDocument/codeLens`
- Capability: `code_lens_provider` with `CodeLensOptions(resolve_provider=False)`
- Handler: `features/code_lens.py` → `handle_code_lens` (version-matched `tree=doc.valid_ast`)
- Setting: `codeLensEnabled` (default `true`); toggles send `workspace/codeLens/refresh` when the client advertises `workspace.codeLens.refreshSupport`

| Lens          | Shown when                                | Command                  |
| ------------- | ----------------------------------------- | ------------------------ |
| Convert to v6 | buffer version is not v6                  | `pynescript.convertToV6` |
| Smoke /run    | editor reports Pro enabled (`proEnabled`) | `pynescript.runOnPro`    |

The handler scans the AST for declaration calls (function bodies are ignored) and falls back to a line scan when the buffer does not parse, so the header lens survives mid-edit parse failures.
