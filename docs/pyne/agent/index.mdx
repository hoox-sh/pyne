# pyne-agent-worker

## Abstract

**pyne-agent-worker** is the edge **authoring** host: natural language in, script source out. It is a **sister repository** — it does **not** live in this PYNE checkout. Do not look for `pyne-agent-worker/` here.

| | |
|--|--|
| **Repo** | [hoox-sh/pyne-agent-worker](https://github.com/hoox-sh/pyne-agent-worker) |
| **Role** | Write scripts via chat (PYNE Agent) + optional RAG |
| **Runtime** | Cloudflare Workers + Workers AI + optional Vectorize / R2 |
| **AXIS** | Component plugin at `/plugin/axis-pine-agent.js` |
| **In this repo?** | **No** |

## Standalone by default

You do **not** need pyne-worker, trade-worker, or the HOOX mesh to use the agent.

| Mode | Requirement | Behavior |
| --- | --- | --- |
| **Standalone** | AI binding (+ optional KB) | `POST /v1/chat` → Pine; validation skipped |
| **HOOX-enhanced** | + pyne-worker URL or service binding | generate → `POST /run` → fix retries |

`GET /health` returns `"mode": "standalone" | "hoox"`.

## Conceptual model

```text
NL request
   → pyne-agent-worker   (write — sister repo)
   → .pine source
   → PYNE Pro API / pyne-worker / AXIS engine   (evaluate)
```

Standalone mode needs only the Workers AI binding. HOOX / pyne-worker is an optional validate loop (`POST /run` then fix retries). `GET /health` reports `"mode": "standalone" | "hoox"`.

## Relationship to PYNE

- **PYNE** remains the semantic oracle and evaluate contract.
- The agent never ships TradingView® built-in sources in git.
- Knowledge (v5/v6 docs, open corpus ≤ 1000, operator builtin refs) is operator-ingested into private R2 + Vectorize™.
