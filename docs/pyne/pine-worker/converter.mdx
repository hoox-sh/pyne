# Python → TypeScript converter

## Abstract

`pine-worker/scripts/convert-python-to-ts.py` (sister repo, **not** in pynescript) is a **porting accelerator**. It reads Python builtin modules and emits TypeScript scaffolding with `TODO` bodies. It is **not** a verified transpiler.

**[PyneTS](/pyne/docs/pynets) does not use this converter.** New builtins are ported by reading `src/pynescript/ast/evaluator/builtins/` and writing TypeScript by hand, then locking with `bun test`. See [parity](/pyne/docs/pynets/parity).

## Conceptual model

```mermaid
flowchart LR
  PY[Python builtin .py] --> CONV[convert-python-to-ts.py]
  CONV --> STUB[TS stub TODO body]
  STUB --> HUMAN[manual semantics]
  HUMAN --> TEST[parity / bun test]
```

## Interface surface

From the **pine-worker** checkout:

```bash
python scripts/convert-python-to-ts.py \
  path/to/pynescript/src/pynescript/ast/evaluator/builtins/numeric.py
```

The script walks the Python AST and prints a TypeScript module. Redirect to a file only if you intend to finish the bodies.

## Internals

| Path | Role |
| --- | --- |
| `pine-worker/scripts/convert-python-to-ts.py` | Converter (sister repo) |
| `pynets/src/runtime/*.ts` | Current TS library handlers |
| `pynescript/.../evaluator/builtins/` | Oracle |

## Invariants & edge cases

1. Converter output is **not** proof of correctness.
2. Do not commit stubs that silently return `0` / `na` without a test.
3. Grammar stays in PYNE `.g4`; do not let the converter invent parser types.

## Worked examples

PyneTS porting path (preferred):

```bash
# 1. Read Python handler
# 2. Edit pynets/src/runtime/ta.ts (or math / request / …)
# 3. Wire evalCall in src/runtime/interpret.ts
# 4. bun test test/interpret_ta.test.ts
```

## Failure modes

| Symptom | Cause | Fix |
| --- | --- | --- |
| `python pine-worker/scripts/...` in PYNE clone | Script is not here | Clone pine-worker or ignore; use PyneTS hand-port |
| Stub compiles, plots wrong | TODO body | Implement against Python |
