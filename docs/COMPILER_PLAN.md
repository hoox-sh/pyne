## Overview
Historically Pynescript executed scripts using an **AST-walking interpreter** in pure Python. Because Pine Script heavily loops over time series data (bars), that path has high overhead.

We introduce a **Source-to-Source Compilation Step** that compiles Pine Script down to JIT-optimized machine code via **Numba** (`@numba.njit`).

## Architecture

### 1. `CompilerVisitor` (AST to Numba)
We will introduce `src/pynescript/compiler/compiler.py` containing a new AST walker: `CompilerVisitor`.
Instead of evaluating the tree, it will transpile the AST into a raw Python code string utilizing `numpy` arrays.

**Example Transpilation:**
*Pine Script:*
```pine
my_sma = ta.sma(close, 14)
plot(my_sma)
```

*Compiled Python (Generated by `CompilerVisitor`):*
```python
import numpy as np
import numba
from pynescript.compiler.numba_builtins import *

@numba.njit
def execute_script_compiled(open_arr, high_arr, low_arr, close_arr, vol_arr):
    n_bars = len(close_arr)
    my_sma_arr = np.full(n_bars, np.nan)
    plot_0 = np.full(n_bars, np.nan)
    
    for i in range(n_bars):
        my_sma_arr[i] = numba_sma(close_arr, 14, i)
        plot_0[i] = my_sma_arr[i]
        
    return {'plot_0': plot_0}
```

### 2. Numba Built-ins Module
Pine Script's standard library (e.g. `ta.*`, `math.*`) needs to be re-implemented in a way that Numba can aggressively compile. We will create `src/pynescript/compiler/numba_builtins.py` containing `@numba.njit` decorated functions.

*Example:*
```python
@numba.njit
def numba_sma(arr, period, i):
    if i < period - 1:
        return np.nan
    sum_val = 0.0
    for j in range(period):
        val = arr[i - j]
        if np.isnan(val): return np.nan
        sum_val += val
    return sum_val / period
```

### 3. Data Structure Overhaul
We will shift from `PineSeries` (which uses a Python `deque` for history) to flat `numpy` arrays for the compiled execution engine. 
* All built-ins (`open`, `high`, `low`, `close`, `volume`) will be passed in as `numpy` arrays.
* User-defined `var` and `series` variables will be automatically allocated as `np.full(n_bars, np.nan)` outside the main execution loop.

### 4. Integration with `backend/runtime.py`
The `Runtime.run()` method will accept an optional `mode="compile"` flag.
When enabled:
1. Parse the script to an AST.
2. Pass the AST to `CompilerVisitor` to generate the Python code string.
3. Use Python's `exec()` to load the Numba-decorated function into the runtime memory.
4. Convert incoming `ohlcv_data` into flat `numpy` arrays.
5. Execute the compiled function at machine-code speeds.

## Benefits
1. **Speed:** Transitioning from an AST interpreter to a Numba JIT loop over numpy arrays will make script executions and backtests thousands of times faster.
2. **Safety & Debugging:** By compiling to Python first, we can easily inspect the transpiled code for debugging before it gets JIT-compiled into LLVM IR.
3. **Compatibility:** We don't need a heavy external compiler toolchain like Rust or C++; Numba integrates seamlessly with Python.
