## Known interaction (flag for the migration owner)

The working tree has an **uncommitted** `.gitignore` change adding `.oo/`. Ruff
respects gitignore and does not know which files are tracked, so in the working
tree `ruff format --check .` silently skips the four tracked `.oo` files
(448 files scanned vs 472 in the clean extract). This is why the working-tree
`.` result is not authoritative and why the clean extract above was used.

If that `.gitignore` change lands as-is, the repo-wide format gate will
silently stop covering tracked `.oo` files. Suggested fix for the migration
card: ignore only `.oo` runtime state (mirroring the old
`.openorchestrate/state.db*` / `logs/` entries) instead of the whole tracked
directory. Not changed here — outside this card.

Also: because `.oo/` is currently ignored in the working tree, this new proof
file is untracked-and-ignored. Staging it needs `git add -f
.oo/proof/ruff-pin-2026-11-17.md` (or fixing `.gitignore` first).
