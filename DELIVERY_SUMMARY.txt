IMPLEMENTATION APPROACH
================================================================================

ARCHITECTURE:
  ├─ Modular evaluator pattern (already in place)
  ├─ Each group gets dedicated module
  ├─ Handlers registered with namespace prefix
  ├─ Inherited into main NodeLiteralEvaluator
  └─ Testable, maintainable, extensible

PATTERN FOR EACH FUNCTION:
  1. Create handler method (returns dict, list, dataclass, or object)
  2. Register in _build_builtin_map() with full namespace
  3. Write 95%+ coverage tests
  4. Update docs/pinescript_implementation_status.md
  5. Commit and document

TESTING STRATEGY:
  ├─ Unit tests: Isolated function testing with all parameter combinations
  ├─ Integration tests: Actual Pine scripts using new functions
  ├─ Fixtures: Download real scripts using new functions
  ├─ Coverage: Aim for 95%+ coverage per module
  └─ Regression: All existing tests must still pass

DATA STRUCTURES:
  ├─ INPUT: Metadata dicts (default, title, tooltip, min, max, step, etc.)
  ├─ REQUEST: Series data as lists (time-series values)
  ├─ DRAWING: Python dataclasses (Line, Box, Label, Table)
  ├─ STRATEGY: Position/Trade dataclasses with state management
  └─ All registered in global collections/registry for lookup
